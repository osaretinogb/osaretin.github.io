NorQuest capstone · Team project

Solar energy forecasting

Can a community energy team estimate how much electricity a proposed solar installation will generate before committing to an investment?

Business need & stakeholder input

Our client’s questionnaire responses and sample financial model pointed to electricity generation in kWh as a key input. The goal was an investment dashboard where staff or volunteers could compare historical generation with a forecast and use that estimate in their financial projections.

My contribution & progress

I worked on the Python data loaders and helped evaluate public PVDAQ solar records. I checked what each energy column measured, how readings at different time intervals could be compared, and what we needed to join generation to weather. I helped explain why we chose a pilot dataset and what we still needed to verify before training.

What I learned & what I’d do next

A system can have plenty of readings and still be a poor match for a proposed site. Capacity, weather and seasonal coverage can all affect how well a model transfers. I’d compare a regression model with a simple seasonal baseline on later months and show the forecast error alongside the prediction.

Machine Learning II · Individual coursework

Iris clustering

How well can clustering group flowers from their measurements when the algorithm has no species labels?

My experiment

I compared K-Means on four flower measurements with agglomerative clustering on two principal components. PCA combines the original measurements into a smaller set of values so I can show the main patterns on a two-dimensional plot. I used species labels after clustering to help interpret the groupings.

Result & interpretation

Setosa separated clearly in the two-dimensional view. Versicolor and virginica overlapped, which made it harder to draw a clear boundary between them. The PCA and agglomerative setup had a higher silhouette score in my coursework comparison. That score measures how tightly points group together and how far apart the groups are.

What I’d do next

I changed the algorithm and the input features in the same comparison. Next time I’d run both algorithms with and without PCA and score them in a common feature space. That would help me tell which change affected the result.

Analytics · Independent project

Cleaning Nashville housing data

Property data is harder to analyse when dates, addresses and vacancy values are inconsistent and the same sale may appear more than once.

My approach

I wrote a SQL Server script that standardizes sale dates, fills missing property addresses using matching parcel IDs, splits address fields, and uses ROW_NUMBER() to remove repeated sale records.

Result & business value

The script creates consistent fields for grouping sales by date or city. It also puts vacancy values into a consistent format so reports can count those records together.

Data quality & reflection

A parcel can have more than one address in the source. On a production dataset I’d flag conflicting matches for review, log the rows I changed, and compare row counts before and after duplicate removal.
